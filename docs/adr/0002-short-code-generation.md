# ADR-0002: 短码采用「Feistel 格式保留加密」打散自增序列

- **状态**：已接受
- **日期**：2026-09-24
- **修订**：本决策在设计中经过一次修正，原方案（线性同余打散）被评审否决。修正过程见 §5。
- **相关**：US-04, AC-04.2 ~ AC-04.4

## 背景

短码必须同时满足三个要求，彼此存在张力：

1. **无冲突**：短码上有数据库唯一索引，任何冲突都意味着一次失败或重试。
2. **不可枚举**：攻击者不应能从已获得的短码推出其他短码，否则全站链接可被遍历爬取。
3. **固定 6 位**：`62^6 = 56,800,235,584`（约 568 亿），容量充足。

容易满足其中两个，难的是三个同时满足。

## 决策

采用 **数据库自增序列 + Feistel 网络格式保留加密（FPE） + Base62 编码**。

```
MySQL 自增 BIGINT  seq ∈ [0, 62^6)
        │
        ▼
Feistel 网络（36 位分组，8 轮，密钥固定）
   ┌─────────────────────────────────────────┐
   │  输入 x ∈ [0, 2^36)                      │
   │  拆分为两个 18 位半块 L, R                │
   │  重复 8 轮:  (L, R) ← (R, L ⊕ F(R, i))   │
   │  合并回 36 位                            │
   └─────────────────────────────────────────┘
        │
        ▼
Cycle-Walking：若结果 ≥ 62^6，则再次施加 Feistel，
               直到落入 [0, 62^6)
        │
        ▼
Base62 编码，左侧补 '0' 至 6 位  →  "aB3x9K"
```

### 两个关键机制

**Feistel 网络保证双射。** Feistel 结构的性质是：只要轮函数 `F` 是任意函数（无需可逆），整个网络就是**双射**。这是它被选中的根本原因——轮的左右交换保证了信息不丢失，因此不同输入必然产生不同输出。无冲突是**数学保证**，不是概率保证。

**Cycle-Walking 处理非 2 的幂的定义域。** `62^6 ≈ 2^35.72`，不是 2 的幂，Feistel 只能在 2 的幂域上直接工作。Cycle-Walking 是 FPE 领域处理这个问题的标准技术：在 36 位域上做置换，若结果落在合法区间之外就再置换一次，直到落入 `[0, 62^6)`。

正确性：由于 Feistel 在 `[0, 2^36)` 上是一个置换，把它的一个轮换（cycle）限制在子集 `[0, 62^6)` 上仍然是一个置换。期望迭代次数为 `2^36 / 62^6 ≈ 1.21` 次，代价可忽略。

## 理由

### 为什么无冲突必须由数学保证

"随机生成 6 位短码 + 查重 + 重试"的方案，冲突概率随占用率上升：占用 10% 时每次生成约 10% 概率需重试，占用 50% 时平均要试 2 次。

更严重的是**并发下的竞态**：

```
时刻 T1: 请求 A 随机得到 "x7Kp2m"，查询数据库确认未占用
时刻 T2: 请求 B 随机得到 "x7Kp2m"，查询数据库确认未占用
时刻 T3: 请求 A 插入成功
时刻 T4: 请求 B 插入 → 唯一索引冲突 → 创建失败
```

两个请求的查重都通过了，但只有一个能插入。表现为线上偶发的创建失败，且**难以复现**（需要精确的时序重合）。

本方案从根上消除这个问题：短码由数据库自增主键经双射变换得到，天然唯一。

### 为什么必须用 Feistel 而不是更简单的打散

这是本 ADR 的核心。详细见 §5 的修正过程。

## 后果

### 正面

- **零冲突**，创建路径无需查重、无需重试。
- **不可枚举**：短码经过密钥化的 Feistel 置换，从任意数量的已知短码都无法推断其他短码。密钥不泄露的前提下，穷举是唯一攻击方式。
- **可预测的容量**：568 亿条，按每天 100 万条新增可用 1556 年。
- **短码稳定**：纯函数，同一 `seq` 永远映射到同一短码，不随重启或扩容改变。
- **可单元测试**：生成器无随机、无 IO，可以断言双射性质。

### 负面（接受的代价）

- **实现复杂度高于随机方案**：Feistel + Cycle-Walking 约 60 行代码，需要理解其正确性前提。缓解：双射性质有专门的单元测试守护。
- **依赖数据库自增**：创建流程需先 `INSERT` 拿到主键再回写短码。实现上采用"先插入（code 临时占位）→ 拿到 id → 计算 code → 更新"两步，在同一事务内完成。
- **密钥管理**：置换密钥通过环境变量注入。密钥泄露会使短码可被枚举——但因短码本身不是凭证（知道短码就等于可以访问该链接），泄露的实际影响是"链接可被批量爬取"，而非越权访问。
- **容量耗尽后回绕会冲突**：`seq` 达到 `62^6` 后回绕。缓解：监控 seq 水位，接近 80% 时扩展短码长度到 7 位（容量 ×62）。

## 5. 修正过程：为什么否决了线性同余打散

> 这一节记录一次**设计评审发现的缺陷**，以及修正过程。保留它是为了说明一件事：**看起来合理的设计，需要在推演和评审中被检验，而不是写完就算。**

### 原方案

最初选择的方案是线性同余打散：

```
permuted = (seq × A + B) mod 62^6     其中 gcd(A, 62^6) = 1
```

选择它的理由看起来很充分：

- `A` 与 `62^6 = 2^6 × 31^6` 互质时，映射是双射，因此同样"无冲突"。
- 只需一行算术，实现极简。
- 连续 `seq` 的输出在 Base62 空间里看起来是完全跳跃的。

### 缺陷

推演攻击者视角时发现问题：**线性同余映射的相邻输出差值是一个常数。**

```
permuted(seq+1) - permuted(seq) = A  (mod M)
```

无论 `A` 取多大，连续输出的差恒为 `A mod M`。这意味着：

1. 攻击者注册账号，连续创建几条短链，拿到一串**连续的** `seq` 对应的短码。
2. 对这些短码做 Base62 解码，得到一串 `permuted` 值。
3. 相邻两项相减（模 `M`），直接得到 `A`。
4. 再代入任意一项解出 `B`。
5. 至此整个映射被完全还原，可以枚举全站所有短码。

**"看起来乱"不等于"不可枚举"。** Base62 编码在视觉上打乱了数字，但底层的线性结构完好无损。这是一个典型的把**混淆（obfuscation）**误当成**加密（encryption）**的错误。

### 修正

改用 Feistel 网络。Feistel 是分组密码的标准结构，其安全性建立在：即使 `F` 是完全公开的简单函数，8 轮的迭代结构也使得从输出反推输入不可行（这需要解决一个难以求解的方程组）。密钥参与轮函数，不公开。

**关键区别：**

| | 线性同余 | Feistel |
| --- | --- | --- |
| 相邻输出的差 | 恒为常数 `A` | 无规律 |
| 已知几个输出能否推导映射 | **能**，解二元一次方程组即可 | 不能 |
| 安全性依据 | 无（只是编码） | 分组密码结构 |
| 实现行数 | 1 | ≈ 60 |

### 这个修正带来的流程启示

1. **设计评审要推演攻击者视角**，而不只是验证"功能是否正常"。"功能正常"和"安全"是两个独立的检验维度。
2. **数学性质要验证到正确的层次**。双射性保证了"无冲突"，但**与"不可枚举"完全无关**——原方案用双射性推导出了不可枚举性，这是一个逻辑跳跃。
3. **验收标准必须能区分这两个性质**。AC-04.3 检验唯一性（可自动化）；AC-04.4 检验不可枚举性——后者难以完全自动化验证，本项目的做法是：单元测试验证双射性 + 一个专门的测试断言"相邻短码的数值差不是常数"，把原方案的缺陷固化成一条回归测试。

## 替代方案与放弃原因

| 方案 | 放弃原因 |
| --- | --- |
| 随机 6 位 Base62 + 唯一索引 + 重试 | 冲突率随占用率上升；并发下产生用户可见的偶发失败；需要重试逻辑与上限保护 |
| 自增 ID 直接 Base62 编码 | **完全可枚举**，可遍历全站链接并泄露业务量 |
| 线性同余打散 | 相邻输出差为常数，可被解方程还原（见 §5） |
| UUID / 雪花 ID 截断 | 截断显著提升冲突率，且短码含时间信息可被推断 |
| AES 加密后取模 | AES 定义域是 128 位，取模会破坏双射性，产生冲突 |
| 号段模式（批量取号） | 解决的是"减少数据库交互"，与短码不可枚举无关。**未来创建量达每秒数千次时应叠加此方案** |
| 布隆过滤器查重 + 随机生成 | 未解决并发竞争；且存在假阳性 |

## 6. 实现参数

| 参数 | 值 | 说明 |
| --- | --- | --- |
| 短码长度 | 6 | 可配置，扩展容量时改为 7 |
| 字符集 | `0-9A-Za-z`（62） | Base62 |
| 空间大小 | `62^6 = 56,800,235,584` | |
| Feistel 分组宽度 | 36 位 | `2^36 > 62^6`，最小的可行宽度 |
| 半块宽度 | 18 位 | |
| 轮数 | 8 | 平衡安全性与性能；8 轮已足够抵抗差分类攻击 |
